# Andrew 專案開發規範

## 決策紀錄

當一項選擇會影響使用者可觀察的行為、模組邊界、資料相容性或後續維護時，在 `docs/decisions/YYYY-MM-DD-topic.md` 記錄決策，並在同一次變更更新 `docs/decisions/README.md` 索引。

每份紀錄說明要解決的問題、考慮過的方案、選擇理由、影響與驗證方式。用以下狀態保留決策脈絡。

- `proposed`：列出仍待比較的方案，以及哪個問題或驗證結果能幫助定案。
- `accepted`：記下定案日期、採用的方案與確認依據。
- `superseded`：保留原文，標明被取代的部分，並在新舊決策間互相連結。

## 以里程碑目標安排任務

- 每個 milestone 先寫出「完成後，使用者能做到什麼」與可觀察的驗收條件，再拆成 tasks。Roadmap 列出各里程碑的目標與狀態；任務、依賴及驗收紀錄放在 `docs/milestones/`。
- Task 編號固定，執行順序依目標、相依性、阻礙及新證據調整。例如 M2-3 先於 M2-2 執行時，保留兩個編號，在計畫裡記下原因與新的下一步。取消或延期也保留原項目、狀態與理由。
- 標記完成時附上對應的驗收證據，例如測試結果、可重現的操作或使用者 review。回報進度時列出目前目標、已驗收成果、剩餘工作，以及接下來最能推進目標的 task。

## Rust CLI 介面與驗收

開發 Rust CLI 時，以 `clap` 定義命令、子命令、參數、必填及互斥關係。解析與 help 使用同一份命令樹，在讀取資料、存取網路或寫檔前先驗證語法。

| 入口 | 使用者應能取得的資訊 |
|---|---|
| `--help`、`-h` | 讓人看見工具名稱、版本、用途、語法、參數及可照做的範例。各子命令提供自己的 help。 |
| `--version`、`-V` | 顯示版本及辨識這次建置所需的資訊。 |
| `--skill`、`--skill index` | 兩種用法回傳相同的主題索引，列出每個主題的用途與呼叫方式。 |
| `--skill <topic>` | 讓只有執行檔的 agent 也能完成任務。提供必要輸入、可執行命令、預期輸出、副作用、結束碼，以及失敗後如何處理。 |

說明入口應可離線執行，無須設定檔或憑證。成功顯示說明時以 0 結束；未知旗標或主題以 2 結束，並提示有效用法。

驗收時在乾淨目錄執行編譯後的 CLI，檢查頂層與子命令 help、兩種索引、所有列出的主題及錯誤輸入。從索引選一個主要流程，依指引提供測試資料並實際執行，核對結束碼、輸出與產物。
